## 已实施

1. MCP 信息列表工具默认跳过精确计数，省略 `include_total` 时返回 `total_count: null`；显式传 `true` 仍计算精确总数。REST 默认 `true` 保持兼容，浏览器首次加载的总数显示保持原有行为。
2. OpenAPI 参数增加 `x-mcp-default: false`，工具发现 schema 与实际调用统一读取该默认值；同步更新 `llm/` 文档和生成资产。其他工具参数默认行为不变。
3. 新增迁移 `0016_works_project_id.sql`，建立 `works(project_id, id)` 索引，改善按项目、ID 游标分页。状态、模板、更新时间过滤继续使用原有查询语义。
4. 日志清理按 `ScheduledController.scheduledTime` 每 5 分钟执行，避免运行延迟改变调度判断；事件投递继续每分钟执行。
5. 单次日志清理按到期时间排序，每批最多 500 条主记录、最多 5 批，遇不足一批即停止；保留每 5 分钟最多 2,500 条主记录的清理能力。关联日志块仍级联删除。该上限按主记录计算，并不限制关联日志块总数。

MCP 调用方如依赖总数，需要显式传 `include_total=true`。游标及返回数据语义不变；降低日志清理频率主要减少空查询，不能按降频比例推算删除行数节省。

| 指标 | 迁移前 | 迁移后 |

| 返回条数 | 101 | 101 |

本次样本读取行数减少约 **93.8%**。耗时仅是单次样本，不能视为稳定延迟基准。
