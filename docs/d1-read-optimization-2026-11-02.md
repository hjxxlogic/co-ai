# D1 普通倒序分页读取优化（2026-11-02）

状态：已于 UTC 2026-11-02 06:53 部署到生产；无需数据库迁移。

## 问题与实现

按创建时间倒序翻页时，SQL 原有 `created_at <= snapshot` 与 OR 游标条件组合可能让索引从快照时间开始扫描，重复读取已翻过的较新记录。生产完整列表 SQL 的只读样本显示：返回相同 101 条，读取 2,203 行；收紧扫描上界后读取 203 行，完整 JSON 哈希一致，样本读取量减少约 90.8%。这不是全天节省率或稳定延迟基准。

`src/items.ts` 在完成可选精确计数后，对 `order=newest` 且有游标的列表查询，将原有创建时间上界绑定值收紧为 `min(snapshot, cursor.time)`。保留严格时间/ID 游标条件，按原快照生成下一页游标。计数继续使用完整筛选集合和原快照。

本次未改变 API 参数、计数默认值、返回结构或索引。更新时间排序、正序及 ID 分页没有套用此优化。全文搜索也可满足收紧后的时间条件，但其 FTS 候选扫描与临时排序瓶颈仍需另外评估。
